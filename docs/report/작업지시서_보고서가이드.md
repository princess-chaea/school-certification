## 3. 보고서의 뼈대 (정해진 방향 — 바꾸지 말 것)

- **제목**: 참(CHAM) 잘했어! 하주 꿈 퀘스트
- **브랜드**: 하주초 비전 「삶의 역량을 기르는 따뜻한 하주 CHAM교육」의 4대 교육목표를 그대로 인증 영역으로 사용
  - **C**reative 배움의 즐거움 → **도전! 독서 마라톤** (특색 [독서] 날마다 리딩)
  - **H**appy 배려와 나눔 → **탄소중립! 환경 지킴이**
  - **A**bility 꿈과 끼 → **Speak up in English** (특색 [영어] Fun Fun한 잉글리쉬)
  - **M**ost 인성·품격(자기관리역량) → 세 퀘스트를 **스스로 기록·성찰하고 인정받는 과정**
- **장 구성** (화북초 양식 그대로)
  1. 운영 개요: 가. 도입 배경(학교 비전/스스로/더 높이) · 나. 학교의 목표(C·H·A·M) · 다. 로드맵 5단계(운영 준비→퀘스트 설정→도전·기록→인증·수여→습관 형성)
  2. 들여다보기: **M**(자기관리·운영 절차) · **CHA**(세 퀘스트·학년별 기준) · **참**(참 잘했어: 인정 문화·인증서)
  3. 결론 및 제언: 가. 운영 성과 + 학교장→교육장→교육감 연계 · 나. 기대 효과(**C·H·A·M 4칸**) · 다. 일반화 3항목
- **수미상관**: 시작(학교의 목표 C·H·A·M) ↔ 끝(기대 효과 C·H·A·M 4칸), 마지막 문장은 제목과 같은 **‘참(CHAM) 잘했어!’**로 끝냄

## 4. 사실 근거 (지어내지 말고 이 안에서만 쓸 것)

### 4-1. 퀘스트와 인증 기준 (하주초 운영 계획)

| 퀘스트 | 대상 | 동장(=학교장 인증) 기준 | 은장 | 금장 |
|---|---|---|---|---|
| 도전! 독서 마라톤 (독서기록장 1쪽 = 1편) | 전 학년 | 1학년 30편(2학기부터) · 2학년 50편 · 3~4학년 40편 · 5~6학년 30편 | 동 × 1.5 | 동 × 2 |
| 탄소중립! 환경 지킴이 (실천 사진 + 소감) | 전 학년 | 20회 (주 1회 이상) | 30회 | 40회 |
| Speak up in English (과제 4개) | 4~6학년 | 과제 2개 완료 | 3개 | 4개 |

- 영어 과제: ① 오늘의 카툰 한 문장(45문장 중 30문장, **EBSe 카툰 잉글리시 2.0 Day 1~45 영상**을 보고 문장 쓰기·3회 녹음 후 검사 요청) ② 알공(완료 화면 캡처) ③ 교과서 주요문장 40개(해석 보고 타이핑·녹음) ④ EBSe 펀리딩 낭독(2분 이상, 4권)
- 은·금 배수(×1.5, ×2)는 웹앱 기본값. 학교에서 바꿨다면 그 값으로 고칠 것

### 4-2. 운영 방식 (실제로 구현·운영된 것)

- 학생: 학교 구글 계정으로 로그인 → 사진·글·녹음으로 기록 → 홈에서 퀘스트별 진행 막대와 STAGE(동·은·금) 확인 → [내 기록]에서 돌아보기
- 교사: 담임은 우리 반, 전담(영어)은 담당 퀘스트 확인. **AI 1차 확인**(사진·글이 활동과 맞는지 표시, 교사만 봄) 후 **교사가 최종 승인**, 여러 건 한꺼번에 승인, 보충이 필요하면 이유와 함께 돌려보냄, **선생님 한마디**를 남기면 학생 홈에 표시
- 태블릿이 없는 학생은 교사가 관찰 후 **일괄 체크**로 기록
- 인증: 기준을 채운 날짜가 들어간 **학교장 인증서가 학생 화면에 즉시** 나타남 → 학기말에 수여 날짜를 정해 인증서를 **일괄 출력·수여**
- **포인트·순위표·학교 화폐·상품 없음** (작년 화북초와 가장 큰 차이 — 심사 기준 ③에 정면으로 부합)
- 운영 현황: 학년·반·항목별 참여율·인증률·금은동 인원이 자동 집계 → **보고서 숫자는 웹앱 [현황]에서 옮긴다**
- 웹앱 주소: https://school-certification.vercel.app (다른 학교도 학교코드로 개설해 함께 사용 가능)

### 4-3. 지어내면 안 되는 것

- 참여·인증 인원, 비율, 운영 성과 수치 → 반드시 웹앱 [현황] 실제 값
- 학생·교사·학부모 소감/인용 → 실제로 받은 말만 (없으면 넣지 않음)
- 교육장 인증 연계 내용, 수여 행사 이름·날짜, 학교 전화번호 → 담당자 확인

- 전체 목록은 `작업자료/photos_v2.json` (문서 순서대로 52개).

## 6. 쓰기 규칙

1. **주인공은 인증제다.** 앱(웹앱)은 도구로만 짧게. ‘개발’, 프로그래밍·서버 용어(Firebase, React, API, 스크립트 등)는 쓰지 않는다. (작년 화북초 보고서가 개발기에 가까웠던 점을 피함)
2. 외적 보상(포인트·순위·상품·화폐) 표현을 쓰지 않는다. ‘인정·격려·인증서·한마디·어제의 나와 비교’로 쓴다.
3. 문장은 짧게, 상자 안은 1~3줄. 보고서 어미는 ‘~함/~했다/~합니다’를 장마다 섞지 말고 원래 상자의 어미를 따른다.
4. 학교 특색(CHAM, 독서·영어)과 교육과정 연계(국어·아침 독서, 창체·환경교육, 영어 교과서·EBSe, 3~12월 연중 운영)를 한 번 이상씩 드러낸다.
5. 인성 교육(배려·나눔·자기관리·품격)을 기대 효과와 결론에 드러낸다.
6. 기존 표·도형·그림 배치는 건드리지 않고 글자만 바꾼다. 쪽이 넘치면 내용을 줄여서 맞춘다.

## 8. (선택) 글자를 다시 일괄 교체할 때

한글에서 직접 고치는 것이 가장 쉽다. 스크립트로 다시 만들려면:

```bash
# 1) hwpx 풀기
mkdir work && cd work && unzip ../원본.hwpx && cd ..
# 2) map json(글자 조각 순번 → 문구)과 사진 안내 json으로 다시 묶기
python3 작업자료/fill_hwpx2.py work 원본.hwpx 결과.hwpx 작업자료/map_v2.json 작업자료/photos_v2.json
```

- 순번은 `Contents/section0.xml`의 `<hp:t>` 순서다. 한글에서 문단을 추가·삭제하면 순번이 바뀌므로 이 방법은 그 전에만 쓴다.
- hwpx 검증: `npx -y kordoc@4.21.15 validate 결과.hwpx`
